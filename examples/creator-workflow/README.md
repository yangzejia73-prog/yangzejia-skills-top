# End-to-end example: 职场博主的“第一次做管理者”选题

本示例使用虚构账号资料，不代表真实用户或采用数据。

## Creator brief

- 定位：帮助刚晋升的一线管理者解决沟通和协作问题
- 受众：工作 3–8 年、第一次带团队的中文职场人
- 平台：小红书和微信公众号
- 目标：产出一篇有明确方法、不过度承诺的内容
- 已有证据：创作者自己的复盘记录；尚无外部调查数据

## 1. Topic research

请求：

```text
使用 topic-research，根据以上定位提出 8 个选题。没有真实热度数据，
所以不得声称选题正在流行。标记每个选题需要补充的证据。
```

预期特点：候选选题应围绕真实读者问题；“需求强度”只能作为待验证假设。

## 2. Source-backed outline

选择选题：“第一次带团队，别急着证明自己：先建立三个工作约定”。提供脱敏复盘记录后，要求生成大纲。

预期特点：个人复盘应被标记为第一手经验，不应被包装成普遍规律；需要外部证据的结论进入待核实清单。

## 3. Platform drafts

- 使用 `xiaohongshu-draft` 生成短版本。
- 使用 `wechat-article` 生成长版本。
- 使用 `content-repurpose` 检查两个版本是否改变核心事实。

预期特点：不得虚构“带过上百人”等资历，不得承诺照做就能晋升。

## 4. Risk review

发布前使用 `content-risk-review` 检查：

- 第一手经验是否被误写成普遍事实；
- 是否出现没有依据的数据；
- 是否泄露同事、公司或客户信息；
- 标题是否承诺确定结果；
- 两个平台版本是否保留必要限定。

## Definition of done

内容只有在事实、隐私、归属和高风险表述均由创作者人工确认后，才进入发布流程。本仓库中的 Skills 不负责登录或发布。
